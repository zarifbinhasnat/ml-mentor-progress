## 🧠 CONCEPT OF THE DAY — THE VENDING MACHINE

**Intuition.** A vending machine takes a continuous input (how hard you push the button) and returns a discrete output (snack B4). Nudging your finger a tiny bit changes nothing, until it suddenly changes everything. That is a derivative that is zero almost everywhere and undefined at the jumps, and backprop has nothing to work with. Every discrete decision in a network (pick a class, round a weight, sample a latent, route a token to an expert, take an action) has this problem. The roadmap contains four different cures:

- **Relax the choice (Phase 1, 5; Phase 8).** Replace argmax by softmax, a smooth surrogate. Add temperature $\tau$ and Gumbel noise and you get a differentiable *sample*.
- **Lie about the gradient (Phase 7: quantization, QLoRA).** Do the hard rounding in the forward pass, but pretend it was the identity in the backward pass: the straight-through estimator (STE).
- **Move the randomness outside (Phase 8: VAE).** Write the sample as a deterministic function of the parameters and an independent noise source, so the gradient flows through the function and not through the dice.
- **Estimate the gradient without differentiating the choice (Phase 11: REINFORCE/PPO).** The score-function trick needs only $\nabla\log\pi$, never $\nabla$ of the sampled action. MoE routing (76) sits between these: top-$k$ is hard, but the *gate weights* of the chosen experts are differentiable, so the router learns through those.

**The math.** Four formulas, one per cure.

Softmax relaxation of $\arg\max$, with temperature $\tau$ and logits $z_i$:

$$p_i=\frac{e^{z_i/\tau}}{\sum_j e^{z_j/\tau}},\qquad \tau\to0\ \Rightarrow\ \text{one-hot}\ \arg\max$$

Gumbel-max trick: if $g_i=-\log(-\log u_i)$ with $u_i\sim U(0,1)$, then $\arg\max_i(z_i+g_i)$ is an exact sample from $\mathrm{softmax}(z)$, and replacing $\arg\max$ by $\mathrm{softmax}(\cdot/\tau)$ makes it differentiable.

Straight-through estimator for a quantizer $q$ with clip range $[-c,c]$:

$$q'(x)=0\ \text{a.e.}\quad\longrightarrow\quad \widehat{\tfrac{\partial q}{\partial x}}=\mathbf 1[\,|x|\le c\,]$$

Here $\mathbf 1[\cdot]$ is the indicator function (1 if the condition holds, else 0). The backward pass treats $q$ as the identity inside the clip range and as a wall outside it.

Reparameterization for a Gaussian latent:

$$z=\mu_\theta+\sigma_\theta\,\epsilon,\quad \epsilon\sim\mathcal N(0,1)\ \Rightarrow\ \frac{\partial z}{\partial\theta}=\frac{\partial\mu_\theta}{\partial\theta}+\epsilon\,\frac{\partial\sigma_\theta}{\partial\theta}$$

Score-function (REINFORCE) estimator, with $f$ a reward that is never differentiated and $b$ a baseline:

$$\nabla_\theta\,\mathbb E_{a\sim\pi_\theta}[f(a)]=\mathbb E\big[(f(a)-b)\,\nabla_\theta\log\pi_\theta(a)\big]$$

Subtracting any $b$ that does not depend on $a$ keeps the estimator unbiased (because $\mathbb E[\nabla\log\pi]=0$) and cuts the variance. That variance is the price paid for not needing a differentiable $f$.

**Why it matters / where it leads.** All four cures trade something: relaxation is biased at $\tau>0$ and the hard sample no longer matches what you trained, STE is biased with no guarantee of descent, reparameterization is unbiased and low-variance but needs a continuous latent, and the score function is unbiased but high-variance. A good answer to "how do you train through a discrete step?" names the cure *and* its failure mode. This thread also explains why VQ-style tokenizers need extra tricks (commitment loss, codebook EMA, which ties back to Day 135) and why PPO clips its ratio.

## 🐍 PYTHONIC EDGE

**Trick: implement the straight-through estimator in one line with `.detach()`, instead of writing a custom autograd function.** The identity is $y = x + \operatorname{sg}(q(x)-x)$, where $\operatorname{sg}$ means stop-gradient: the value equals $q(x)$ and the gradient equals that of $x$.

```python
import torch                                    # plain import; C++ would be #include <torch/torch.h>

# BAD: round() has zero gradient, so nothing upstream ever learns
def fake_quant_bad(x, delta):                   # def, no types or braces; indentation is the block
    return torch.round(x / delta) * delta       # '/' is true division on tensors, no integer-division surprise

# CLEAN: forward value is quantized, backward sees the identity
def fake_quant(x, delta, lim=1.0):              # default argument value; C++ has this too but Python evaluates it once at def time
    q = torch.clamp(torch.round(x / delta) * delta, -lim, lim)   # clamp is out-of-place; the _-suffix version would mutate
    return x + (q - x).detach()                 # detach() cuts the graph for this term: value q, gradient 1

x = torch.linspace(-1.0, 1.0, 7, requires_grad=True)   # keyword argument; requires_grad marks a leaf to track
y = fake_quant(x, 0.5)
y.sum().backward()                              # populates x.grad in place
assert torch.equal(x.grad, torch.ones(7))       # assert raises AssertionError on False; no NDEBUG switch like C++
assert (fake_quant_bad(x, 0.5).detach() == y.detach()).all()   # same forward values, different gradients
```

The class form is what you use inside a model, and it shows the OOP mechanics:

```python
class FakeQuant(torch.nn.Module):               # C++: class FakeQuant : public torch::nn::Module
    def __init__(self, bits=4, lim=1.0):        # constructor; 'self' is C++'s 'this' but explicit
        super().__init__()                      # parent constructor; C++ uses an initialiser list
        self.delta = 2 * lim / 2 ** bits        # '**' is exponentiation (C++ needs std::pow); precedence is above '*' and '/'
        self.lim = lim                          # attribute created by assignment; C++ declares it in the class body

    def forward(self, x):                       # the hook nn.Module calls; never call it directly
        return fake_quant(x, self.delta, self.lim)   # a plain function used as a first-class callable

layer = FakeQuant(bits=3)                       # no 'new'; calling the class constructs the object
out = layer(torch.randn(4))                     # layer(...) runs __call__, which wraps forward() with hooks
```

## 📡 SIGNAL LAB

**Problem.** A $b$-bit uniform quantizer with step $\Delta$ rounds a signal. (a) Model the error and give its power. (b) By how many dB does the noise floor drop per extra bit, and what is the SQNR of a full-scale sine? (c) Under what conditions does the "white noise" model break? (d) Why does that matter for detecting spectral artifacts of generated images?

**Solution.**

(a) If the signal is busy enough that the rounding error $e$ is uniform on $[-\Delta/2,\Delta/2]$ and uncorrelated with the input, then

$$\sigma_e^2=\frac{1}{\Delta}\int_{-\Delta/2}^{\Delta/2}e^2\,de=\frac{\Delta^2}{12}$$

and the error spreads evenly across frequency, so its PSD is flat at $\Delta^2/12$ (for the normalisation used in the script).

(b) With range $2c$ and $\Delta=2c/2^b$, each extra bit halves $\Delta$, so the power drops by $4\times$ (6.02 dB). A full-scale sine has power $c^2/2$, giving

$$\mathrm{SQNR}\approx 6.02\,b+1.76\ \text{dB}$$

In the script: the 4-bit error variance measured $1.42\times10^{-3}$ against $1.30\times10^{-3}$ predicted, and 8-bit $6.85\times10^{-6}$ against $5.09\times10^{-6}$. The measured floor drop from 4 to 8 bits is **23.2 dB** against the theoretical 24.1 dB. The small excess comes from a few samples of the noisy test signal exceeding the clip range, which adds clipping error on top of rounding error.

(c) The model needs the signal to cross many quantization levels. For a low-amplitude or exactly periodic signal the error is deterministic and correlated with the input, so it concentrates into harmonics instead of a flat floor. Adding a little dither (noise of about one $\Delta$) restores the white model at the cost of a slightly higher floor. This is exactly why the STE gradient is "wrong but fine": it treats the rounding error as noise independent of the input.

(d) An 8-bit image has $\Delta=1/255$ on a $[0,1]$ scale, so $\Delta^2/12\approx1.3\times10^{-6}$, a floor near $-59$ dB per pixel. Upsampling artifacts of a generator that sit *below* that level are wiped out by saving to 8-bit PNG, and ones that survive stand above a flat floor. JPEG is worse because it quantizes in the DCT domain with larger, frequency-dependent steps, which is a non-white, high-frequency-biased floor.

**So what.** In your frequency-domain forensics work, compare spectra of generated images **after** the same 8-bit pipeline the real images went through. Otherwise a detector may learn "float32 versus 8-bit" instead of "generated versus real". A flat residual floor near $\Delta^2/12$ is your sanity check that the pipeline is clean.

## 🏋️ THE GAUNTLET

**Top K Frequent Elements** (the selection step of top-$k$ routing, done on counts). Given an integer array `nums` and an integer `k`, return the `k` values that appear most often, in any order. It is guaranteed that the answer is unique, i.e. there is no tie that straddles the $k$-th place.

Constraints: $1\le n\le10^5$; $-10^4\le\texttt{nums}[i]\le10^4$; $1\le k\le$ number of distinct values. Aim for better than $O(n\log n)$.

**Hints.**
1. First turn the array into value → count pairs. What is the cheapest structure for that?
2. Sorting all pairs by count costs $O(d\log d)$ for $d$ distinct values. A heap of size $k$ gives $O(n\log k)$. What do you know about the *range* of possible counts that sorting does not exploit?
3. A count can never exceed $n$. If you index a structure by count, what does "walk from the highest count down until you have $k$ values" cost in total?

**Pattern:** frequency map + bucket sort by count (or size-$k$ min-heap as the $O(n\log k)$ fallback).

**Target:** $O(n)$ time, $O(n)$ space.

## 🔓 GAUNTLET SOLUTION

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> topKFrequent(vector<int>& a, int k) {
    unordered_map<int,int> cnt;
    for (int x : a) ++cnt[x];                   // value -> frequency
    vector<vector<int>> bucket(a.size() + 1);   // bucket[f] = values appearing exactly f times
    for (auto& [v, c] : cnt) bucket[c].push_back(v);
    vector<int> out;
    for (int f = (int)a.size(); f >= 1 && (int)out.size() < k; --f)
        for (int v : bucket[f]) {
            out.push_back(v);
            if ((int)out.size() == k) break;
        }
    return out;
}
```

Compiled and run: `[1,1,1,2,2,3], k=2` → `{1, 2}`; checked against a sort-based brute force on 3000 random small arrays (cases with a tie across the $k$-th place skipped, matching the uniqueness guarantee). Counting is $O(n)$, filling buckets is $O(d)\le O(n)$, and the descending walk visits at most $n$ bucket slots plus $d$ values, so the total is $O(n)$ time and $O(n)$ space.

## 💡 CONCEPT ANSWER

**Not a bug, a deliberate approximation.** The true gradient of rounding is zero almost everywhere, which would freeze every weight below the quantizer. STE substitutes the identity inside the clip range, so the full-precision "shadow" weights receive the gradient computed at the quantized point and drift until they cross a rounding boundary. The forward pass always uses the real quantized values, so the loss you optimise is the loss you deploy.

**When it works.** The step $\Delta$ is small relative to the scale of the loss landscape (8 or 4 bits with sensible per-channel or per-group scales), the shadow weights are kept in higher precision (fp16/fp32), and the learning rate is small enough that updates are not swamped by the rounding. The rounding error then behaves like small input-independent noise, as in the Signal Lab.

**When it fails.** At very low bit-widths (2 bits, binary), where $\Delta$ is large and the error is neither small nor independent of the input, the gradient can point in a direction that does not reduce the quantized loss and training oscillates. It also gives no signal for weights outside the clip range, which are masked to zero gradient and can get stuck.

**What to check first when loss stalls.** (1) Is the clip range or scale sensible? If most weights are clipped the STE mask zeros their gradients, so look at the fraction inside $[-c,c]$. (2) Are the shadow weights actually being updated in full precision, rather than being re-quantized and overwritten by the optimiser? (3) Is the learning rate small relative to $\Delta$, so that updates ever cross a rounding boundary, but not so large that they bounce between levels? (4) Compare quantized and fp32 loss on the same batch to see whether the gap is a scale problem or an STE problem.
