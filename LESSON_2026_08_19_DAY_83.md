# Day 83 — Diffusion: Forward Noising

## 🧠 CONCEPT OF THE DAY

**Intuition.** Imagine slowly dissolving a photograph into TV static — not in one violent jump, but in hundreds of tiny, gentle steps, each one adding just a whisper of Gaussian noise on top of the last. After enough steps, the "photograph" is indistinguishable from pure noise. That's the **forward diffusion process**: a fixed, non-learned Markov chain that destroys structure a little at a time. It's the *easy* half of a diffusion model — no neural net required, just a noise schedule. The hard, learned half (reversing it) is tomorrow's concept.

**The math.** At each step, we add a small amount of Gaussian noise controlled by a variance schedule $\beta_t \in (0, 1)$:

$$q(x_t \mid x_{t-1}) = \mathcal{N}\!\big(x_t;\ \sqrt{1-\beta_t}\,x_{t-1},\ \beta_t I\big)$$

Here $x_0$ is the real data point, $x_t$ is its state after $t$ noising steps, and $\beta_t$ (small, e.g. $10^{-4}$ to $0.02$) is how much noise step $t$ injects. Note the $\sqrt{1-\beta_t}$ shrinkage on the mean — this isn't cosmetic. It's what makes the process **variance-preserving**: as noise variance grows, signal variance shrinks to compensate, so $x_t$ never blows up or decays to zero regardless of how large $t$ gets.

Chaining $t$ of these Gaussian steps has a closed form (Gaussians compose nicely), letting us define:

$$\alpha_t = 1 - \beta_t, \qquad \bar\alpha_t = \prod_{s=1}^{t}\alpha_s$$

and jump **directly** from $x_0$ to any $x_t$ in one shot:

$$q(x_t \mid x_0) = \mathcal{N}\!\big(x_t;\ \sqrt{\bar\alpha_t}\,x_0,\ (1-\bar\alpha_t) I\big)$$

Using the reparameterization trick (Day 79 called back), this is sampled as:

$$x_t = \sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\epsilon, \qquad \epsilon \sim \mathcal{N}(0, I)$$

$\bar\alpha_t$ is the fraction of *original signal variance* still present at step $t$; $(1-\bar\alpha_t)$ is the noise variance. As $t \to T$, $\bar\alpha_t \to 0$ and $x_T$ is indistinguishable from $\mathcal{N}(0, I)$ — pure noise, by design.

**Why it matters / where it leads.** That closed-form shortcut is the single most important engineering fact in diffusion training: you never simulate $t$ sequential noising steps. You sample one random $t$, draw one $\epsilon$, and compute $x_t$ in O(1). Tomorrow (Day 84) we flip this around — train a network to predict $\epsilon$ (or $x_0$) from $x_t$, which is the entire denoising objective that makes generation possible. This closed form is also *why* diffusion models are so much more stable to train than GANs (Day 82): there's no adversarial game, just regression against a known, fixed target.

**Interview question:** *Why does the forward process rescale the mean by $\sqrt{1-\beta_t}$ instead of simply adding noise, i.e. $x_t = x_{t-1} + \sqrt{\beta_t}\,\epsilon$? What would go wrong at large $t$ if you didn't?*

## 🐍 PYTHONIC EDGE

The trick above — computing $\bar\alpha_t$ as a running product — is exactly what `np.cumprod` / `torch.cumprod` is built for. The bad way loops in Python; the clean way vectorizes.

```python
import torch

betas = torch.linspace(1e-4, 0.02, 1000)  # slice notation not needed here, but linspace returns a 1-D tensor object
alphas = 1.0 - betas                       # elementwise: NOT a loop, unlike C++ where you'd write a for-loop over indices

# --- bad way: explicit Python loop, O(T) Python-level overhead ---
alpha_bars_slow = []
running = 1.0
for a in alphas:                # `for x in tensor` iterates elements — no index/iterator boilerplate like C++'s for(auto& a : v)
    running *= a                 # `*=` in-place-looking, but `running` is a Python float, rebound each time (no true mutation)
    alpha_bars_slow.append(running.item())  # .item() pulls a Python scalar out of a 0-d tensor; no such unboxing needed in C++

# --- clean way: vectorized cumulative product, O(T) but no Python-level loop ---
alpha_bars = torch.cumprod(alphas, dim=0)   # dim=0, not axis=0 (torch convention vs numpy's `axis=`)
# ** below is exponentiation, NOT XOR like C++'s ^
sqrt_alpha_bars = alpha_bars ** 0.5
sqrt_one_minus = (1 - alpha_bars) ** 0.5

def forward_sample(x0: torch.Tensor, t: torch.Tensor, alpha_bars: torch.Tensor) -> torch.Tensor:
    # t is a LongTensor of shape (batch,); alpha_bars[t] does fancy/advanced indexing —
    # no C++ equivalent without writing an explicit gather loop
    ab = alpha_bars[t].view(-1, *([1] * (x0.dim() - 1)))  # *([1]*n) unpacks a list into view()'s varargs — tuple/list unpacking
    eps = torch.randn_like(x0)      # same shape/dtype/device as x0 — no manual shape bookkeeping needed
    return ab.sqrt() * x0 + (1 - ab).sqrt() * eps
```

A minimal class wrapper, annotated for the OOP mechanics that differ from C++:

```python
class GaussianDiffusion:                    # single inheritance shown implicitly (no base here); C++: class GaussianDiffusion { ... }
    def __init__(self, T: int = 1000, beta_start: float = 1e-4, beta_end: float = 0.02):
        # self is explicit here — C++'s implicit `this` is never spelled out in the signature
        self.T = T                            # instance attribute: created on assignment, no header declaration needed
        betas = torch.linspace(beta_start, beta_end, T)
        self.alpha_bars = torch.cumprod(1.0 - betas, dim=0)   # stored for reuse — like a member initialized in a ctor body

    def __call__(self, x0: torch.Tensor, t: torch.Tensor) -> torch.Tensor:
        # calling diffusion(x0, t) invokes __call__ — this is the dunder analog of nn.Module's __call__/forward split
        assert t.max() < self.T, "t out of range for this schedule"   # assert: stripped under `python -O`, unlike C++ assert macro nuance
        return forward_sample(x0, t, self.alpha_bars)
```

## 📡 SIGNAL LAB

Since you already think in spectra: the forward process has a clean frequency-domain reading, and it's the seed of Day 88 (spectral signatures of generated images).

**Setup.** Your clean signal $x_0$ has a power spectral density (PSD) concentrated at a few frequencies (it's structured, band-limited). Additive white Gaussian noise $\epsilon$ has a **flat** PSD — equal power at every frequency. The forward process at step $t$ gives:

$$x_t = \sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\epsilon$$

Because scaling and independent addition are linear, the PSD of $x_t$ is:

$$S_{x_t}(f) = \bar\alpha_t \cdot S_{x_0}(f) + (1-\bar\alpha_t)\cdot S_\epsilon(f)$$

where $S_\epsilon(f)$ is flat (constant power at every $f$, by definition of white noise). Define the frequency-resolved SNR:

$$\text{SNR}(f, t) = \frac{\bar\alpha_t\, S_{x_0}(f)}{(1-\bar\alpha_t)\, S_\epsilon(f)}$$

**Worked insight.** At small $t$, $\bar\alpha_t \approx 1$, so $\text{SNR}(f,t)$ is high everywhere the signal has power (low/mid frequencies for natural images) and near-zero at frequencies the signal never occupied. As $t$ grows, $\bar\alpha_t \to 0$ uniformly across *all* $f$ — the flat noise floor rises and swamps the signal's peaks **starting at the frequencies with the least original power** (typically the high frequencies — fine detail, edges, texture) and eating inward toward the dominant low frequencies last.

**So what:** this is precisely why diffusion-generated images have a *telltale spectral signature* — the reverse (denoising) process is trained to reconstruct high frequencies from a regime where they were the first to disappear and the hardest to recover exactly, so generated images tend to have a distinctively different high-frequency spectral falloff than camera-captured images (which acquire high-frequency content directly from optics/sensor noise, not from a denoiser's best guess). This is the exact mechanism GAN/diffusion image forensics tools exploit (e.g. detecting a suspicious "notch" or unnatural decay in the radially-averaged PSD). File this away — Day 88 formalizes it.

## 🏋️ THE GAUNTLET

**Problem: Running Signal Power (Product of the Last K Multipliers)**

You're implementing $\bar\alpha_t$ online: multipliers $\alpha_1, \alpha_2, \dots$ arrive one at a time (each $\alpha_i \in [0, 1]$, and — this is the twist — occasionally exactly $0$, representing a "reset" step in the schedule). You must support two operations, called in any order, up to $10^5$ times total:

- `add(alpha)`: append a new multiplier $\alpha_i$ to the stream.
- `getProduct(k)`: return $\prod$ of the last $k$ multipliers added (product of the $k$ most recent values). It's guaranteed $k \le$ number of values added so far.

**Constraints:** $0 \le \alpha_i \le 1$ (so no negative numbers to worry about, but zeros are allowed and must be handled correctly — a zero anywhere in the last $k$ values makes the product $0$). Aim for **O(1) amortized** per `add` and **O(1)** per `getProduct`.

**Hint 1:** A naive prefix-product array (`prefix[i] = prefix[i-1] * alpha[i]`) lets you answer `getProduct(k)` as `prefix[n] / prefix[n-k]` in O(1) — but think hard about what breaks the instant any $\alpha_i$ in your history is exactly $0$.

**Hint 2:** When a zero arrives, everything before it becomes "unreachable" for division purposes (you'd divide by zero). What if you just... started a *new* prefix-product list from scratch right after a zero, and kept the old one around only far enough back to answer in-range queries?

**Hint 3:** Track the size of your current "zero-free" prefix list. If `getProduct(k)` asks for more values than exist since the last zero, you already know the answer without doing any arithmetic — what is it?

**Pattern:** running prefix product with a **zero-reset sentinel** (this is LeetCode-family "Product of the Last K Numbers"). Target: `add` O(1) amortized, `getProduct` O(1).

🔓 GAUNTLET SOLUTION

```cpp
#include <vector>
using namespace std;

class ProductOfNumbers {
public:
    ProductOfNumbers() {
        prefix.push_back(1.0);   // prefix[0] = 1 (empty product), sentinel base
    }

    void add(double alpha) {
        if (alpha == 0.0) {
            // zero resets the zero-free run: start a fresh prefix list from 1
            prefix.clear();
            prefix.push_back(1.0);
        } else {
            prefix.push_back(prefix.back() * alpha);
        }
    }

    double getProduct(int k) {
        int n = (int)prefix.size() - 1;   // number of values in the current zero-free run
        if (k > n) {
            // window spans a zero from an earlier (now-reset) run
            return 0.0;
        }
        return prefix[n] / prefix[n - k];
    }

private:
    vector<double> prefix;
};
```

**Why it works:** every `add` is O(1) amortized (a single multiply-and-push, or an O(1) clear+push on the rare zero). `getProduct(k)` is O(1): if the current zero-free run is shorter than `k`, the true window must include a zero we already discarded, so the answer is trivially `0` with no arithmetic. Otherwise it's a plain prefix-product division — exactly the $\bar\alpha_t / \bar\alpha_{t-k}$ trick used to recover a partial noise schedule slice without recomputing a running product from scratch.

💡 CONCEPT ANSWER

Without the $\sqrt{1-\beta_t}$ shrinkage, $x_t = x_{t-1} + \sqrt{\beta_t}\,\epsilon_t$ is a **pure random walk**: its variance grows *unboundedly* as $\text{Var}(x_t) = \text{Var}(x_0) + \sum_{s\le t}\beta_s$, and its mean stays fixed at $x_0$ forever. At large $t$ you'd get an enormous, ever-growing-variance blob centered on the original data point — never converging to a clean, fixed reference distribution. By contrast, the actual update $x_t = \sqrt{1-\beta_t}\,x_{t-1} + \sqrt{\beta_t}\,\epsilon_t$ is a **variance-preserving (mean-reverting) process**: the shrinkage on $x_{t-1}$ exactly compensates for the injected noise variance, so total variance stays bounded (converging to $\approx 1$ if data is normalized), and the mean is pulled toward $0$ as $t \to T$. This guarantees $x_T \sim \mathcal{N}(0, I)$ **regardless of what $x_0$ was** — which is exactly the fixed, sampleable prior the reverse process needs to start generation from.
