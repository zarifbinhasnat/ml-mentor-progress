# Day 91 — Concept 91: SimCLR

## 🧠 CONCEPT OF THE DAY

**Intuition.** Yesterday CLIP pulled an image and its caption together while pushing every other caption away. SimCLR asks: what if you don't have captions at all? Take one unlabeled image, hit it with two *different* random augmentations (a crop, a color jitter, a blur) to make two views of the same underlying scene, and tell the network "these two views are the same thing — every other image in the batch is not." No labels, no text encoder, just an image, its own distorted reflection, and a crowd of decoys. The representation that falls out of solving this "spot your own twin in a lineup" game turns out to be good enough to fine-tune into a strong classifier with only a handful of labeled examples — because to consistently recognize a heavily cropped, recolored version of itself among a batch of unrelated images, the network is forced to discard nuisance detail (exact color, exact framing) and keep whatever *semantic* content survives both augmentations.

**The math.** Given a minibatch of $N$ images, sample two random augmentations per image to get $2N$ views total. Pass each view through a shared encoder $f$ (a ResNet backbone) and a small projection head $g$ (an MLP, discarded after pretraining) to get $z = g(f(x))$. For a positive pair $(i, j)$ — the two views of the same source image — define cosine similarity $\text{sim}(z_i, z_j) = \frac{z_i \cdot z_j}{\lVert z_i\rVert \lVert z_j\rVert}$, and the **NT-Xent** (normalized temperature-scaled cross-entropy) loss for that pair:

$$\ell(i,j) = -\log\frac{\exp(\text{sim}(z_i, z_j)/\tau)}{\sum_{k=1}^{2N}\mathbb{1}_{[k\neq i]}\exp(\text{sim}(z_i, z_k)/\tau)}$$

The denominator sums over all $2N{-}1$ other views in the batch — the other $2(N{-}1)$ images' two views each are the negatives, and no explicit negative mining is needed because everything not-$j$ is automatically a negative. Total loss averages $\ell(i,j)$ over both orderings of every pair. This is *exactly* CLIP's InfoNCE machinery from yesterday, with the two modalities (image, text) replaced by (view A, view B) of the same image — the batch is still the entire negative set, temperature still controls selectivity, and batch size still matters enormously for the same reason.

**Why it matters / where it leads.** SimCLR is the cleanest proof that contrastive pretraining doesn't need paired multimodal data — just a good augmentation policy and enough negatives, which is why it kicked off the modern self-supervised pretraining wave (MoCo, BYOL, and Wednesday's DINO all descend from this recipe). The projection head $g$ is thrown away after training specifically because it's optimized to make the *contrastive task* easy, which discards information a downstream task might need — the frozen backbone $f(x)$, not $g(f(x))$, is what gets fine-tuned. It also sets up tomorrow: MAE (masked autoencoders) shows you can get comparable representations from an entirely different self-supervised objective — reconstruct missing patches instead of matching augmented views — no contrastive negatives required at all.

**Interview question:** *SimCLR discards the projection head $g$ after pretraining and fine-tunes only the backbone $f$. Concretely, what goes wrong on a downstream linear-probe classification task if you keep $g$'s output and skip discarding it — and why does that failure mode specifically implicate what the contrastive loss optimizes $g$ to throw away?*

## 🐍 PYTHONIC EDGE

The NT-Xent loss is "cosine similarity matrix over $2N$ views, minus each view's own diagonal, then cross-entropy against the known positive index" — and the diagonal-masking step is exactly where a naive implementation either double-counts a view against itself or silently mismatches indices between the two augmented halves of the batch.

```python
import torch
import torch.nn.functional as F

# ---- BAD: Python double for-loop, self-similarity masked with a magic number ----
def nt_xent_bad(z, temperature):
    n = z.shape[0]                                            # n = 2N total views (N images x 2 augmentations)
    loss = 0.0
    for i in range(n):                                        # O(n^2) Python-level loop -- no vectorization, brutally slow on GPU
        sims = []
        for k in range(n):
            if k == i:
                continue                                      # skip self -- easy to get wrong once augmentation order shifts
            cos = F.cosine_similarity(z[i].unsqueeze(0), z[k].unsqueeze(0))
            sims.append(cos.item() / temperature)              # .item() pulls a Python float off the GPU -- syncs device every call
        pos_idx = i + n // 2 if i < n // 2 else i - n // 2     # positive pair index: fragile arithmetic assumption about view ordering
        loss += -sims[pos_idx] + torch.logsumexp(torch.tensor(sims), dim=0).item()
    return loss / n

# ---- CLEAN: vectorized similarity matrix + boolean mask, no Python-level loop ----
def nt_xent_clean(z, temperature):
    n = z.shape[0]                                             # n = 2N views; z assumed already L2-normalized (F.normalize(z, dim=-1))
    sim = (z @ z.t()) / temperature                             # @ is matmul (not C++'s bitwise &); one (n, n) similarity matrix, all pairs at once
    self_mask = torch.eye(n, dtype=torch.bool, device=z.device) # torch.eye -> identity matrix; dtype=torch.bool makes it directly usable as a mask
    sim.masked_fill_(self_mask, float("-inf"))                  # in-place (_-suffix) exclude self-similarity from every row's softmax denominator
    targets = torch.arange(n, device=z.device)
    targets = (targets + n // 2) % n                            # each view's positive is its augmentation partner, n//2 seats away, wrapping via %
    return F.cross_entropy(sim, targets)                        # softmax + NLL in one call, same machinery as Day 5's cross-entropy

z = F.normalize(torch.randn(8, 128), dim=-1)                    # 8 views = batch of N=4 images, 2 augmented views each
loss = nt_xent_clean(z, temperature=0.5)                        # a scalar tensor; call .backward() on it during training, not shown here
```

`nt_xent_bad` is $O(n^2)$ in *Python*, not just in the math — every `.item()` call forces a GPU-to-CPU sync, and the hardcoded `n // 2` offset silently breaks the moment the two augmented halves aren't laid out in that exact order. `nt_xent_clean` does the identical math as one matrix multiply plus a masked softmax, which is also precisely how you'd batch today's Signal Lab experiment across many crop scales at once instead of looping in Python.

## 📡 SIGNAL LAB

**Worked insight.** SimCLR's signature augmentation is `RandomResizedCrop`: crop a random (often small) sub-region of the image, then bilinearly resize it back to the target resolution. Bilinear interpolation is a **low-pass filter** in exactly the DSP sense — it's a weighted local average, which attenuates any content near the resampled grid's Nyquist frequency. The graph makes this concrete: a synthetic image with a smooth base plus a fine checkerboard texture (the classic signature of transposed-convolution upsampling artifacts, à la Day 43/Day 88) has its high-frequency energy spread all the way out to the Nyquist corners at `scale=1.0`, and that same energy collapses into a tight, low-frequency-only blob by `scale=0.2` — the corners go dark because the resize step simply never reconstructs frequency content that fine from a small cropped patch.

**So what.** This is a genuine trap for your frequency-domain forensics work specifically: the checkerboard/grid artifacts that distinguish GAN- or diffusion-upsampled images from real camera images live *exactly* at the high-frequency end of the spectrum that `RandomResizedCrop` attenuates. If you self-supervise a feature extractor with the standard SimCLR augmentation recipe and then reuse that backbone for real-vs-generated spectral forensics, the pretraining objective actively taught the network to treat the very artifact you want to detect as noise to discard — because two augmented views that disagree on high-frequency content still need to be pulled together by the contrastive loss, so the easiest solution is for the encoder to stop encoding that content at all. The practical fix in forensics-adjacent SSL work is to either weaken/remove aggressive resizing crops in the augmentation pipeline, or add a frequency-aware augmentation-invariance check as a diagnostic before trusting an SSL-pretrained backbone's high-frequency sensitivity.

## 🏋️ THE GAUNTLET

**Couples Holding Hands.** `n` couples sit in one row of `2n` seats, numbered `0` to `2n-1`. Couple `i` consists of people `2i` and `2i+1`. You're given `row`, where `row[i]` is the ID of the person currently in seat `i`. Return the minimum number of swaps (each swap exchanges any two people) so that every couple sits in adjacent seats.

**Constraints:**
- `2n == row.length`, `2 <= n <= 30`, `n` is even
- `0 <= row[i] <= 2n - 1`, all values distinct

**Hints (escalating):**
1. Group the row into `n` adjacent seat-pairs (seats `2k, 2k+1` for each `k`). For each seat-pair, look at which two *couples* currently occupy it — every seat-pair "belongs" to whichever couple-index each occupant's ID maps to (person `p` belongs to couple `p // 2`). What relationship does a seat-pair holding two different couples' members imply about those two couples?
2. Build a graph on the `n` seat-pair positions: if seat-pair $k$ currently holds one member of couple $A$ and one member of couple $B$ ($A \neq B$), draw an edge between $A$'s "home" and $B$'s "home." This graph decomposes into disjoint cycles (a seat-pair already holding a correctly matched couple is a self-loop / isolated node contributing nothing). What's the minimum number of swaps to fully resolve one cycle of length $k$?
3. A cycle of length $k$ takes exactly $k - 1$ swaps to resolve (each swap fixes one seat-pair and shrinks the cycle by one). You don't need to build the graph explicitly or find cycles by traversal — **Union-Find** gets you the same answer directly: union the two couple-indices found at each seat-pair, then the answer is `n - (number of connected components)`.

**Pattern:** Union-Find over an implicit "who's out of place with whom" graph, answer derived from component count rather than explicit swapping simulation. **Target complexity:** $O(n \cdot \alpha(n))$ time (inverse-Ackermann, effectively constant), $O(n)$ space.

## 🔓 GAUNTLET SOLUTION

```cpp
#include <bits/stdc++.h>
using namespace std;

class DSU {
public:
    vector<int> parent, rank_;
    DSU(int n) : parent(n), rank_(n, 0) {
        iota(parent.begin(), parent.end(), 0);   // each couple starts as its own component
    }
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);  // path compression
        return parent[x];
    }
    void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (rank_[a] < rank_[b]) swap(a, b);
        parent[b] = a;
        if (rank_[a] == rank_[b]) rank_[a]++;
    }
};

int minSwapsCouples(vector<int>& row) {
    int n = row.size() / 2;
    DSU dsu(n);
    for (int seatPair = 0; seatPair < n; ++seatPair) {
        int coupleA = row[2 * seatPair] / 2;
        int coupleB = row[2 * seatPair + 1] / 2;
        dsu.unite(coupleA, coupleB);
    }
    int components = 0;
    for (int i = 0; i < n; ++i) {
        if (dsu.find(i) == i) components++;
    }
    return n - components;
}
```

Each seat-pair contributes one union operation ($O(\alpha(n))$ amortized), then one pass counts root nodes. A cycle of $k$ couples collapses into one component and needs exactly $k-1$ swaps to fix, so summing $(k_c - 1)$ over all cycles $c$ telescopes to `n - components` — no explicit cycle detection or swap simulation needed.

## 💡 CONCEPT ANSWER

Keeping $g$'s output for a downstream linear probe hurts because the contrastive loss actively optimizes $g$ to become **invariant to exactly the augmentations used during pretraining** — color, crop, blur — which means $g(f(x))$ has been trained to *throw away* information like color statistics, exact spatial layout, and fine texture, precisely because those are the nuisance variables the augmentation policy perturbs. That's fine for the pretext task (matching two views of the same image), but plenty of downstream tasks need exactly that discarded information — a flower-species classifier needs color, a texture-defect detector needs fine spatial detail. The backbone $f(x)$, one layer earlier, hasn't been forced through that same invariance bottleneck, so it retains a richer, more general-purpose representation that a linear probe can still carve up correctly. Empirically this is exactly what the SimCLR paper measures: linear-probe accuracy using $f(x)$'s representation consistently beats using $g(f(x))$'s, which is the direct evidence that the projection head is disposable pretraining scaffolding, not part of the useful representation.
